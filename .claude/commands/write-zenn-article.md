あなたはZenn記事執筆の専門家です。質の高い技術記事を作成し、読者にとって価値のある内容に仕上げてください。

## 入力情報
$ARGUMENTS

## 実行手順

### 1. 記事の準備
- 既存の記事を編集する場合：該当ファイルを読み込み
- 新規作成の場合：`npx zenn new:article --slug [slug-name]`で作成
- TodoWriteツールで作業をトラッキング

### 2. 記事の構成と執筆

#### 記事の基本構造
- **frontmatter設定**：
  - title: 読者の興味を引く、逆説的または具体的なタイトル
  - emoji: 記事内容を表す絵文字
  - topics: 最大5個、関連性の高いものを選択
  - published: false（初期状態）
  - published_at: 公開予約時に設定

- **heading構造**：記事本文はheading2（##）から開始

#### 文章スタイル
- カジュアルですます調で統一
- 冗長な箇条書きは避け、自然な文章にする
- AI臭さを排除し、人間らしい文章を心がける
- 具体例や実体験を積極的に含める

### 3. 記事の強化ポイント

#### 説得力を高める要素
- **具体的な数値やデータ**：効果測定、ROI、時間短縮の実例
- **失敗談と学び**：実際の経験から得た知見
- **長期的視点**：将来的な価値や拡張性への言及
- **図表の活用**：ER図、フロー図、比較表など

### 4. 推敲と校正

#### チェックポイント
- 論理的な流れと一貫性
- 表記統一（漢字/ひらがな、送り仮名）
- 重複表現や冗長な部分の削除
- 読者視点での分かりやすさ

### 5. 公開準備

#### プレビュー確認
```bash
npx zenn preview
```

#### 公開設定
- 即時公開：`published: true`
- 予約公開：`published_at: "YYYY-MM-DD HH:MM"`

#### Gitコミット
適切なコミットメッセージで変更を記録：
- 新規記事の場合：「記事追加: [タイトル]」
- 更新の場合：「記事更新: [変更内容]」

## 記事作成のベストプラクティス

1. **読者ファースト**：読者が抱える課題や疑問に答える
2. **実践的な内容**：理論だけでなく実装例や手順を含める
3. **独自の視点**：個人の経験や考察を加える
4. **継続的な改善**：フィードバックを受けて記事を更新

## 注意事項
- 記事ファイルは`articles/`ディレクトリに保存
- slugは英数字とハイフンのみ使用
- 画像を使う場合は適切なalt属性を設定
- コードブロックには適切な言語指定を行う
